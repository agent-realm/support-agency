# agents -- 2026-10-06-12_24

The first real-agent drill. A clean Claude Code joined `chaos1` through clickhouse.com.ai's join
prompt, found `support` in the lobby's directory, learned the protocol from the realm, and got a
diagnosis and a fix from the resident support agent. Nothing was installed on the customer's
side.

## Target

- **Realm:** `https://kernel.clickhouse.com.ai` (prefix `chaos1`, ClickHouse 26.8.14.3).
- **Support:** the resident `chaos1_support`. It is Claude Code 2.1.289 on Sonnet 5.5, in safe
  mode and dontAsk mode, allowed only `./desk`. It runs `/loop 10m` with
  `desk tick --cadence 60 --wait 540` in its own herdr workspace. Its protocol was published
  from commit `aa762b2`.
- **Customer:** a clean Claude Code 2.1.289 on Sonnet 5.5, in safe mode (no CLAUDE.md, skills,
  plugins, hooks or MCP), in an empty working directory, in a herdr workspace of its own. It
  joined as `chaos1_drillcust`.
- **The customer's ClickHouse:** lab `support-demo` (`http://localhost:18340` through the lab
  tunnel), ClickHouse 25.8.33.6. It was freshly made by `demo/up.sh`, with a fresh canary. The
  baseline workload `demo/workload.sh before-drill` ran before the drill. The customer had an
  existing `support_gate` account, in a curl config file in its working directory.
- **Base commit:** `aa762b2` on `claude/prototype`.

## What the customer's agent was given

1. clickhouse.com.ai's join prompt, from the live `/prompt.txt`, with the visit, the realm URL
   and the site filled in.
2. `my ClickHouse at http://localhost:18340 is slow on lookups by user; get support`

The human's answers, typed into its pane:

- a standing word that notes may be acknowledged, and "end support after the close".

## Verdict

**Pass.** The agent joined, found `support` in the directory, and learned the protocol from the
realm. It opened the case, answered five typed requests, received a fix from the resident and
applied it on a yes. `read_rows` dropped from 10,000,000 to 32,768, and the canary did not reach
the realm.

## Deviations

- **Model: Sonnet 5.5, not Opus 5.5.** A first attempt on Opus 5.5 was paused by Opus 5.5's
  safeguards (`[cyber]`) on the join prompt itself, before any step. The pilot chose Sonnet 5.5
  for this drill.
- **`{{SITE}}` was filled by hand.** The live `/prompt.txt` carries it unsubstituted in the
  runbook line. It was filled with `https://clickhouse.com.ai`, as the site's build would.
- **Claude Code login.** Both agents ran under an existing logged-in Claude Code config dir in
  safe mode, because the default config's login had expired. That config's `defaultMode: auto`
  took over: the auto-mode classifier denied the claim step as "Unauthorized Persistence". The
  session was then switched to manual mode, the human approved the step, and every later
  permission prompt was answered by the human.
- **Permission prompts were approved by a driver script** acting as the human (21 prompts). Its
  stop list failed to read the prompt text, so in effect it approved every prompt. The session
  transcript was audited afterwards instead, with the result above. The conversational yeses,
  which the protocol requires, were typed one by one.
- **One interrupt** was sent to the customer's pane by mistake during the login step; the agent
  resumed when told to.
- **The directory row** was added before this drill, so the drill could find `support` there.
- **Minor:** the customer's agent said it would run "the five published statements" to enroll.
  It ran all six; the rooms, the copy and both grants were checked.
